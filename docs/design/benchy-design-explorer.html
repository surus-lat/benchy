The Design

Four peers, one composition.

Every benchmark framework before benchy picked the model as its primitive and shipped other people's benchmarks. Benchy inverts both: the primitive is the AI-system — model, node, workflow, or agent — and the product is authoring benchmarks, the translation layer between a business problem and the system that solves it. Click a module to trace it.

benchy.task
the exam contract
what shape does a solution have?
Input/output schema and prompt scaffolding. Never data, never scoring, never inference details.
Task(input=ImageIn(), output=InvoiceExtraction, domain, language)
benchy.scoring
the rubric as program
what does correctness mean?
A symbolic expression — composable, introspectable, transformable. Not a class-per-rubric.
evaluate() → breakdown · fitness() → float · aggregate() · repr round-trips
benchy.system
the opaque program
what are we grading?
One protocol hides model, node, workflow, agent. Transports, venvs, loaders are plumbing.
System.load("openai:…" | "hf:…" | "./agent.py:Agent") → run(sample)
benchy.data
the evidence
what do we grade against?
Sample streams satisfying the task schema. Loading, caching, validation, splits.
Data(source="hf:…" | local | synth, schema=task.schema)
schema ↓
fitness ↓
predictions ↓
samples ↓
benchy.Benchmark
The only object that ties the four peers together. Fixes task, scoring, and data — the system is the free variable, so a benchmark is already almost a loss function.
runnableawait bench.run(limit=200) executes + scores per sample
exportablebench.as_loss() → (system, examples) → float for DSPy / TextGrad / GEPA
serializableround-trips to a 4-field YAML, no hidden state

The authoring workflow

The developer's mental model, mirrored 1:1 by CLI and SDK. No mention of interfaces, adapters, providers, pipelines, checkpoints, runners, or probes — those are plumbing under the hood.

# CLI $ benchy new image_extraction/invoices/es-AR # scaffold benchmark.yaml + scoring.py $ benchy run image_extraction/invoices/es-AR --system openai:gpt-5-mini $ benchy export-loss image_extraction/invoices/es-AR --to dspy # SDK import benchy as b task = b.Task.load("image_extraction/invoices/es-AR") scoring = b.field_wise_weighted(fields=INVOICE_FIELDS, weights=WEIGHTS) data = b.Data.load("./data/invoices/*.pdf", schema=task.schema) system = b.System.load("openai:gpt-5-mini") result = await b.Benchmark(task, scoring, data, system).run()

The ontology

/<task?>/<domain?>/<language?> — the organizing structure for naming, filesystem layout, and registry lookup. Every level is optional; missing levels are implied.

image_extraction/ invoices/ es-AR
transcription/ fleurs?/ pt-BR?
transcription/ ·/ ·
  • Filesystem — benchmarks/<task>/<domain>/<language>/benchmark.yaml
  • Registry key — image_extraction/invoices/es-AR
  • Task level — not a magic string; references a Task shape declared in benchy.task
  • Domain + language — pure organizational labels

The reference example

The sanity check for whether four modules and their composition are actually enough. If this can't be expressed end-to-end, the design fails.

  • Task — input Image, output InvoiceExtraction (vendor, total, due_date, line_items…)
  • Scoring — default field_wise over invoice fields; weighted variant (total×3, due_date×2) for business view; binary(default) for a perfect-extraction leaderboard
  • Data — ~200 real Argentine invoice PDFs with ground-truth JSON
  • System — any VLM via System.load: raw model, model+prompt node, or pre-processing agent
Decisions

What's locked, what's open.

The two beliefs are non-negotiable — everything else is a decision with options, a recommendation, and a consequence. Open decisions get resolved with concrete code during milestone 1, not in the spec.

Dependencies

Nine milestones, two gates.

Milestones are demo-shaped, not layer-shaped — each ends with a runnable command. Nothing destructive lands before a gate. Click a node to inspect it; edges show what unblocks what.

Consequences

~18k lines in, ~2.5k out.

The salvage audit judges every area of the current tree against the vision. The ratio is not a mistake: the old code solved running benchmarks against many models on many frameworks — and the vision says benchy is not that project.

KEEP ~1.2k ADAPT ~0.8k NUKE ~16k

One run, end to end

How the choices compose when the reference benchmark executes.
$ benchy run image_extraction/invoices/es-AR --system openai:gpt-5-mini --limit 5 task registry resolves ontology path → pydantic InvoiceExtraction schema data local source streams PDFs → validated against task.schema (fail loud) system "openai:" scheme → OpenAISystem → run(sample) per image scoring field_wise_weighted.evaluate(pred, truth) per sample → aggregate() report scoring report printed · benchmark.yaml untouched · result serializable
belief 1The system swap is one flag. Node, workflow, or agent would run identically — the run loop never learns which shape it graded.
belief 2The benchmark was authored, not downloaded: schema, rubric, and evidence all named explicitly in the ontology path.
loss hookThe same objects power bench.as_loss() — task fixes contract, data fixes evidence, scorer fixes fitness.
absentNo interface, adapter, provider, pipeline, checkpoint, runner, or probe appears. Plumbing stayed under the hood.
